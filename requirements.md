## Aclaraciones

Estas son las reglas que el profesor ha definido para el proyecto de libreria de grafos.
Para ver la guía de estilo del proyecto, dirigirse a las [styleguides.md](./styleguides.md).

## Introducción

Crear una librería que permita implementar grafos de manera rápida y sencilla en cada una de sus implementaciones (Listas y Matriz de adyancencias), incluyendo diferentes algoritmos de recorrido,calcular camino más corto entre dos nodos y cualquier función relevante.

La librería debe de permitir crear  objetos de una manera fácil y sencilla para el usuario de CUALQUIER TIPO DE DATO que el quiera, y debe ser resistente a fallos como: out of index, overflow y cualquier error de memoria posible.

En resumen, una librería "incluir y usar" para trabajar con grafos. 

## Consideraciones

- La entrega es por medio del enlace a un repositorio.

- El proyecto debe de tener su propio README.md.

- El proyecto debe de seguir la siguiente estructura de carpetas: una carpeta bin
  donde se generara el ejecutable y donde estan los datos, una carpeta src donde solo
  debe de estar el codigo del proyecto.

- El trabajo es en pareja o individual.

- Si el trabajo se hace en pareja, la diferencia de commits entre ambos no debe
  ser gigante, es decir, si uno de los dos tiene el 90% de los commits y el otro el 10%,
  la nota completa será para la primera persona y la segunda se evaluara según el
  trabajo que hizo y que de verdad se use en el programa final entregado.

- Los commits tienen que tener el formato visto en clase, de no tenerlo se pueden
  reducir hasta 4 puntos.

- Si un proyecto solo tiene un commit, asumiré que se hizo un día antes y no hubo
  el debido análisis del proyecto, entonces evaluaré el proyecto en base a 10, lo
  mismo se aplica para commits hechos un día antes de la entrega.

- No se pueden utilizar vectores.

- Cada requisito no cumplido quita 4 puntos, las observaciones relacionadas a la
  entrega del proyecto no cumplida quita 2 puntos.

- Los nombres de los archivos del programa sin símbolos especiales ni espacios,
  solo snake_case o camel_case, lo mismo aplica para las carpetas.

- Hasta que el usuario lo diga el programa debe de seguir ejecutandose.

- El proyecto debe de tener ya unos datos para probar la aplicación.
